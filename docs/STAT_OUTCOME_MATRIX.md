# PROJECT V — 능력치 → 결과 케이스 (수식 명세)

**기준일:** 2026-11-19 · **범위:** 라운드 내 교전·설치 후 판단. 맵은 Ascent, 스킬은 기본 off.

엔진 원칙(풋볼매니저식): 결과를 먼저 정하지 않는다. 모든 결과는 **선수 능력치 × 상황 × 전술 판단**에서
나오고, 각 단계는 아래 수식 하나로 설명된다. 능력치는 0–1 척도이고 **리그 평균 0.6**인 선수는 각 수식의
기본값을 그대로 받는다.

### 2.1 양각(크로스파이어) — 힉-하이먼 법칙

선택지가 늘면 반응시간이 로그로 늘어난다.

```
반응 지연 = b · log2(n + 1) · (1 − 1.25·(gameSense − 0.6))
```

- `n` = 결투 상대 외에 나를 겨눌 수 있는 적 총구 수. 나를 실제로 보고 있거나 나까지 **선이 열린**
  (`lineOfSight`, 위치 기반 — 2026-11-23부터. 이전에는 Zone 시야선 표) 적 중에서
  - 자리 잡고 **정지**한 적은 1,
  - 이동 중이지만 결투 상대와 **30° 이상 다른 방향**에서 오는 적은 1,
  - 같은 방향으로 뒤따라 달려오는 적은 0.2(양각이 아니라 트레이드 압박)로 센다.
- `b` = 60ms/bit (옵션 `crossfireMsPerBit`).
- 양각에 걸린 쪽은 프리에임 이점도 잃는다.

| 상황 | 결과 |
|---|---|
| 총구 1개 추가, gameSense 0.6 | +60ms |
| 총구 2개 추가 | +95ms |
| 총구 4개 추가 | +139ms |
| gameSense 1.0 | 지연 절반 |
| gameSense 0.2 | 지연 1.5배 |

### 2.2 정보 — 지수 감쇠(반감기)

```
w = 2^(−경과시간 / 반감기),   반감기 = 2000ms · (1 + 1.5·(trading − 0.6))
먼저 못 본 쪽의 기습 지연 = 300ms · (1 − w)
```

- 팀이 그 적을 본 적이 있고, 적이 그 구역을 떠나지 않았을 때만 정보가 있다.
- `w ≥ 0.5`(반감기 이내)면 상대의 프리에임도 무효가 된다(위치를 알고 조준하며 진입).
- 정보가 없으면 `w = 0` → 기습 지연 300ms 전부 + 상대 프리에임. **정보 없는 영역 먹기는 도박이다.**

| 상황 | 결과 |
|---|---|
| 방금 콜된 위치로 진입 | 지연 0, 상대 프리에임 없음 |
| 2초 전 콜 | 지연 150ms |
| 4초 전 콜 | 지연 225ms, 상대 프리에임 유지 |
| trading 1.0 | 반감기 3.2초 |
| trading 0.2 | 반감기 0.8초 |

### 2.3 클러치 — 마지막 생존자 vs 2명 이상

```
반응 보정 = (0.6 − clutch) · 250ms      (clutch 1.0 → −100ms, 0.2 → +100ms)
```

음수 보정은 다른 지연(양각·기습)을 상쇄하는 데만 쓰이고 0 아래로는 내려가지 않는다.

### 2.4 앵글 어드밴티지와 피커스 어드밴티지 (옵션 아님)

코너와 지연이 있으면 반드시 생기는 효과라 경기 전 옵션이 아니다.

```
앵글:  Δt = (몸 반폭 35 ÷ 옆걸음 속도) × (1 − 피커의 코너 거리 ÷ 홀더의 코너 거리)
피커스: 정지한 홀더는 움직이는 상대에게 180ms 늦게 반응 (보정 집계값)
```

| 상황 (달리기 피킹, 피커는 코너에서 3m) | 결과 |
|---|---|
| 홀더가 6m 뒤 | 피커 +26ms |
| 홀더가 30m 뒤 | 피커 +47ms |
| 홀더가 코너 1m에 붙음 | 홀더 +104ms (상한) |
| 걸어서 피킹(속도 절반) | 지연 약 2배 |

선수 능력치는 이 기하를 바꾸지 못한다. 위치 선택(깊게 잡기, 넓게 피킹)이 바꾼다.

### 2.5 소모전(옵션)

```
결투 후 체력 = 체력 − carryover · (이번 결투에서 입은 피해)
```

`damageCarryover` 기본 **0.4** (2026-11-23, 이전 0). 체력 재생이 없으니 물리적 값은 1이고, 1과의 차이는
결투 사이에 모델링하지 않는 회복(엄폐, 빠지기, 스킬 OFF 모드에 없는 저지)의 대리값이다. 실제 로스터 시드 1–160으로
맞추고 161–320 · 321–480에서 확인했다(`docs/ENGINE_TRUTH.md` §4.2): 0 → 6/8(공격 0.460), 0.4 → 8/8(0.501),
0.7 → 6/8(전멸·해체 이탈), 1 → 설치 0.70 · 해체 0.25. 살아남은 선수는 남은 실드도 그대로 다음 라운드로 가져간다.

### 2.6 발소리 — 거리 규칙 (perception-engine)

```
달리는 선수의 발소리는 3D 거리 d ≤ R 인 모든 적에게 들린다 (벽 통과). 걷기·정지는 무음.
R = 스파이크 폭발 반경        단서 신뢰도 = 1 − d / R
```

- 들리는지는 반경 안에서 전부 아니면 전무다(게임의 감쇠 곡선이 평평해 범위 안의 발소리는 항상 들린다).
  거리가 깎는 것은 **어디인지**에 대한 확신이다 — 바로 옆 1, 반경 끝 0.
- 단서는 구역 수준(그 구역 중심)이고 **달리는 선수 1명당 1개**다. 서로 다른 선수의 발소리는 다른 소리로 구분되지만
  누구인지는 담기지 않는다. 팀 단위로는 장소로 맞춘다: 구역마다 "한 명의 청취자가 그곳에서 들은 최대 수"가 그 구역의
  러너 수다(세 명이 같은 두 명을 들어도 2명). 아군의 발소리는 단서가 아니다.
- 총성·스킬 단서는 이전과 같이 사운드 그래프로 전파된다.
- **R은 확인된 수치가 아니다.** 출처(VALORANT 위키 Spike 문서)는 "폭발의 최대 반경은 플레이어의 오디오 범위와 거의 같다"는
  관계만 적고 숫자를 주지 않는다. 50 m는 달리기 발소리 범위에 대한 비공식 커뮤니티 추정치 하나를 옮긴 **manual-approx**이며
  `game-rules/src/spike.ts`의 `SPIKE_RULES.blastRadiusM`에 `verified: false`로 들어 있다. 라이브 빌드로 검증이 필요하다.

| 상황 (Ascent, R = 50 m) | 결과 |
|---|---|
| A 메인(21 m)에서 달림 | A 사이트에서 들림, 신뢰도 0.58 |
| A 로비(40 m)에서 달림 — 사이트와 소리 연결·시야선 없음 | 그래도 들림(벽 통과), 신뢰도 0.20 |
| B 로비(62 m)에서 달림 | B 사이트에서는 안 들림, 미드 코트야드(42 m)에서는 들림 |
| 같은 자리에서 걸음 | 안 들림 |

코드: `packages/perception-engine/src/hearing.ts`, `packages/round-simulator/src/view.ts`(`teamFootsteps`, `roundPerceptionParams`).

### 2.7 이동 사격 — 정지 시간 (combat-engine)

교전이 시작될 때 움직이고 있던 선수는 **멈출 때까지만** 이동 사격 페널티를 받는다. 예전에는 결투가 끝날
때까지 계속 받았다(존 호핑 엔진에서는 상대 구역에 "도착한" 순간 정지 상태였기 때문에 드러나지 않았고,
실제로 걸어 들어가는 지금은 진입하는 쪽이 항상 이동 사격자가 되었다).

```
정지 시각 = (적을 인지한 시각) + stopMs(이동 방식) × lerp(1.4, 0.6, movement) × movingStopScale
stopMs: 달리기 700ms, 걷기 350ms   (걷기/달리기 속도 비 340 : 675 ≈ 0.5 와 같은 비율)

정지 시각 이전의 사격:  명중률 × (0.55 + 0.45 · movement · 0.5),  헤드샷 확률 × 0.5,  상대에게는 움직이는 표적
정지 시각 이후의 사격:  정지 사격과 동일
```

코드: `packages/combat-engine/src/skills.ts` `stoppedAtMs` / `movingAt`, `params.ts` `accuracy.stopMs`.
`stopMs`는 몸이 멈추는 시간만이 아니라 **이동 중에 걸린 선수가 자리 잡은 선수처럼 싸우게 되기까지**(발을
멈추고 조준이 안정될 때까지)의 시간이라 카운터 스트레이프 한 번보다 길다.

| 능력치 · 상황 | 결과 |
|---|---|
| movement 0.0 | 달리다 멈추는 데 980ms, 그동안 명중률 ×0.55 |
| movement 0.5 | 700ms, ×0.66 |
| movement 1.0 | 420ms, ×0.78 — 잘 움직이는 선수는 빨리 멈추고 이동 중에도 덜 빗나간다 |
| 걸어서 진입 | 정지 시간 절반(350ms) — 조용하고(§2.6) 교전에서도 덜 불리하지만 느리다(§3.7) |
| 늦게 인지(기습·양각으로 지연) | 인지한 뒤에야 멈추기 시작하므로 정지 시각도 그만큼 늦다 |
| 뱅달 vs 뱅달 15m, 동급(5,000회) | 서서 0.607 · 걸어 들어가서 0.467 · 달려 들어가서 0.382 · 끝까지 못 멈추면 0.377 (동률이면 a가 먼저 쏘는 엔진 규칙 때문에 서서가 0.5가 아니다) |

짧은 교전(한두 발에 끝나는 소총 근·중거리)은 멈추기 전에 끝나므로 진입 불리함은 그대로 남고, 길어지는
교전(권총, 원거리, 서로 빗나감)에서 진입자가 회복한다.

**보정.** `stopMs`는 측정값이 아니라 보정값이다. Ascent 160경기(시드 1–160)에서 달리기 정지 시간을
150–1200ms로 바꿔 가며 실측 라운드 결과 분포와 맞췄다(§6): 500ms 이하에서는 공격 승률이 57–65%로 치솟고,
800ms 이상에서는 해체가 실측보다 낮고 피스톨 라운드가 범위를 벗어난다. 경기 전 옵션 `movingStopScale`
(기본 1)로 배율을 바꿀 수 있고, `Infinity`면 예전 모델(끝까지 이동 사격)이다.

## 3. 팀 판단 수식 (team-engine)

코드: `packages/team-engine/src/policy.ts`.

### 3.1 리테이크 vs 세이브 — 란체스터 제곱 법칙

```
P(리테이크) = D² / (D² + κ·A²)        D = 생존 수비, A = 생존 공격, κ = 1
P < 0.15 이면 세이브
```

| 수비 vs 공격 | P | 판단 |
|---|---|---|
| 3v3 | 0.50 | 리테이크 |
| 2v3 | 0.31 | 리테이크 |
| 1v2, 2v4 | 0.20 | 리테이크 |
| 2v5 | 0.14 | 세이브 |
| 1v3 | 0.10 | 세이브 (aggression ≥ 0.75인 선수는 시도, 기준 0.08) |
| 1v4 | 0.06 | 세이브 |

- 이동 + 해체 7초가 폭발 타이머보다 길어도 세이브한다.
- 세이브 콜은 그 라운드 동안 유지되고, 인원이 동수 이상이 되면 다시 리테이크한다.
- 세이브하는 선수는 설치 구역에서 보이지 않는 가장 가까운 구역으로 숨는다.

### 3.2 협동 리테이크 — 최소 노출 접근

설치 구역을 지키는 공격은 그 구역에서 나가는 시야선을 정지·조준 상태로 보고 있다. 그 시야선을 가로지르는
리테이커는 걸음 중에 먼저 보인다(엔진에서 가장 불리한 결투). 그래서 수비수는 설치 구역의 진입로 E마다

```
노출(E) = 경로 (현재 → E → 설치) 중 설치 구역에서 보이는 구역에 머무는 시간의 합
이동(E) = time(현재 → E) + time(E → 설치)
```

을 계산해, `이동 + 해체 7초 + 여유 3초 ≤ 폭발 타이머`인 진입로 중 **노출이 가장 적은 길**을 택한다(같으면 빠른 길).
시간 안에 드는 길이 없으면 가장 빠른 길. 접근로는 리테이크 콜 때 한 번 정하고, 그 길에서 설치 구역이 보지 못하는
마지막 구역에 모였다가 함께 진입한다. 전원이 모였거나 `가장 느린 선수의 남은 이동 + 해체 7초 + 여유 3초 ≥ 폭발 타이머`면 진입.
리테이크 가능 여부(§3.1의 시간 조건)도 최단 경로가 아니라 **택한 접근로**의 시간으로 판단한다.

맵 고유 규칙은 없다. Ascent B는 마켓·링크가 사이트에서 보이고 수비 스폰 쪽은 보이지 않아 스폰 쪽으로 돌아 들어가고,
A는 가든이 보이지 않아 가든으로 들어간다 — 맵의 시야선에서 나오는 결과다.

| 상황 (Ascent B 설치, A 앵커) | 결과 |
|---|---|
| 타이머 45초 | 래프터 → 수비 스폰 → B (노출 0) |
| 타이머가 돌아갈 시간을 못 줌 | 마켓 직행(노출 있음), 미드 바텀에서 집결 |
| 마켓에 시야선이 없는 맵이라면 | 짧은 마켓 길 |

### 3.3 쓰로잉 — 비례위험(해저드) 모델

유리한 자세를 버리고 혼자 나가는 실수. 자세는 세 가지다.

| 자세 | 쓰로잉 |
|---|---|
| 설치 후 공격의 사이트 홀드 | 리테이크 쪽으로 한 구역 나가 피킹 |
| 설치 후 수비의 리테이크 대기 | 집결을 기다리지 않고 혼자 진입 |
| **설치 전, 이미 이긴 라운드의 수비** (공격의 승산 `A²/(A²+κD²)` < 리테이크 최소 승산, 시야에 적 없음) | 자리를 버리고 세이브하는 공격을 쫓아 상대 스폰 쪽으로 달림 |

세 번째는 세이브(§3.6)의 짝이다. 가만히 있으면 시간이 라운드를 끝내 주는데 킬을 잡으러 나가는 것이고,
쫓는 쪽은 자리 잡은 상대에게 걸어 들어가므로 역으로 잡히기도 한다(인원이 동수가 되면 공격은 세이브를 풀고 다시 친다).

```
z = (aggression − 0.5) − (discipline − 0.5) − (decisionMaking − 0.5)
λ = max(최소 쓰로잉률, λ₀ · exp(3·z))        λ₀ = 0.006 /초
결정 1회(0.5초)당 확률 p = 1 − e^(−λ·0.5)
```

| 성향 | 초당 발생률 | 20초 홀드 중 쓰로잉 확률 |
|---|---|---|
| 중립 | 0.006 | 11% |
| aggression 0.9, discipline 0.3, decisionMaking 0.3 | 0.066 | 73% |
| aggression 0.3, discipline 0.9, decisionMaking 0.9 | 0.0003 | 1% 미만 |

**최소 쓰로잉률**은 팀·선수별로 지정한다. 선수의 하한은 팀 값과 선수 값 중 큰 쪽이고,
능력치가 아무리 좋아도 그 밑으로 내려가지 않는다.

### 3.5 계획의 실행 경로 (공격)

- **최소 노출 경로**: 두 후보(최단 경로 / 자기 스폰 경유)의 “사이트가 보는 구역에 머무는 시간”을 비교해 적은 쪽을
  택한다(같으면 빠른 쪽). 사이트를 바꾸는 팀이 방금 치지 않기로 한 사이트를 걸어서 통과하지 않는다.
- **설치는 계획의 사이트에서만**: 캐리어가 다른 설치 가능 구역을 지나가더라도 거기서 설치하지 않는다.
- **페이크**: 소수(2명 — 스파이크를 들지 않은 가장 공격적인 선수)가 보여줄 사이트에서 **보이지 않는 마지막 구역**까지만
  접근해, 그 구역과 바로 뒤 구역 사이를 **일부러 달려서** 소리를 낸다. 본대와 스파이크는 실제 목표 쪽에 조용히 집결한다.
  보여주는 시간(18초)이 끝나면 쇼를 하던 선수들이 돌아와 합류하고, 전원이 모이면 진입한다. 생존자가 3명 미만이면 페이크하지 않는다.
  시야선 안에 서 있는 것은 보여주기가 아니라 계획에 없던 교전이다.
- **도착 후 조준**: 팀 이동 명령은 도착했을 때 볼 구역(목표 사이트)을 함께 가진다.
- **러커**: 로스터에서 가장 소극적인(`aggression` 최저) 1명으로 **지정**한다. 죽어도 대체하지 않고, 생존 3명 이하면
  두지 않는다. 느린 플레이가 사이트를 정하기 전까지만 반대편 접근로(그 사이트에서 보이지 않는 구역)를 잡고,
  사이트가 정해지면 팀에 합류하며 진입은 그를 기다린다.

### 3.6 공격의 세이브 — 란체스터 × 지킬 가치

수비의 리테이크/세이브(§3.1)와 같은 수식을 설치 전 공격에 적용하되, **문턱은 따로 둔다**.

```
P(진입) = A² / (A² + κ·D²)        A = 생존 공격, D = 생존 수비, κ = 1
P < attackSaveMinWinChance(0.09) 이고, 생존자 중 누군가의 무기 가격 ≥ saveMinWeaponValue(1900) 이면 세이브
```

| 공격 v 수비 | P | 소총(2900) | 스펙터(1600)·클래식 |
|---|---|---|---|
| 1v2, 2v4 | 0.20 | 진행 | 진행 |
| 2v5 | 0.14 | 진행 | 진행 |
| 1v3 | 0.10 | 진행 | 진행 |
| 1v4 | 0.06 | 세이브 | 진행 |
| 1v5 | 0.04 | 세이브 | 진행 |

- **왜 수비(0.15)보다 낮은가.** 설치 전의 공격은 아직 스파이크와 사이트 선택권을 쥐고 있고, 실제 경기에서
  시간 초과로 끝나는 라운드는 4.3%뿐이다. 문턱을 수비와 같은 0.15로 두면 1v3·2v5에서도 포기해 시간 초과가
  7–9%로 실측의 두 배 가까이 된다. 0.09는 Ascent 160경기에서 시간 초과 비율을 실측에 맞춘 보정값이다(§6).
- 수비의 추격(엑싯 킬, §3.3)도 같은 문턱을 읽는다: 공격의 승산이 이 값 아래로 떨어졌을 때만 "이긴 라운드"다.
- 영웅 플레이(aggression ≥ 0.75인 마지막 1명)는 `heroMinWinChance`(0.08)와 이 문턱 중 낮은 쪽을 쓴다.
  기본값에서는 둘 사이에 해당하는 인원 구성이 없어 차이가 없고, 문턱을 올린 팀(예: 0.15)에서 1v3을 받아들이는 차이가 난다.
- `saveMinWeaponValue` 기본값 1900은 최소 패배 보너스다. 져도 받는 돈으로 다시 살 수 있는 무기를 위해 라운드를 포기하지 않는다.
- 세이브하는 선수는 자기 스폰으로 물러나 버티고, 시간이 다 되면 수비 승(시간 초과). 콜은 계획 수정으로 기록되고
  그 라운드 동안 유지되며, 인원이 동수가 되면 풀린다. 설치 후에는 세이브하지 않는다.
- 한계: 팀 단위 경제라 세이브한 무기가 다음 라운드로 이월되지는 않는다(행동만 모델링).

### 3.7 걷기 / 달리기 — 결정이다

달리면 빠르고 시끄럽다(§2.6). 걸으면 들리지 않지만 시간이 두 배 든다. 이동 방식은 선수가 실제로 아는 세 가지에서 정한다.

```
의도 = loud (들리려고 — 페이크의 쇼)                         → 달린다
의도 = fast (시간이 승부 — 진입 콜, 리테이크, 추격, 세이브, 급한 로테이션)  → 달린다
의도 = quiet (들키지 않고 도착 — 집결, 러크, 느린 플레이, 조심스러운 로테이션):
    들릴 위치가 아니면 (적이 있다고 믿는 모든 곳에서 R 밖)        → 달린다  (소음이 공짜)
    여유 = 남은 시계 − (걸어서 갈 시간 + 진입 + 설치 + 여유 8초) < 0  → 달린다  (시계가 소음보다 급하다)
    그 외                                                  → 걷는다
```

- "적이 있다고 믿는 곳": 공격은 사이트(수비가 지키는 곳)와 이번 라운드에 본 적의 위치, 수비는 보거나 들은 적의 위치.
- 계획 단계와의 연결: 집결(stage)·러크·느린 플레이 = quiet, 진입(go) = fast, 페이크의 쇼 = loud.
- 개인이 고른 이동은 `aggression > 0.6`이면 fast(속도를 택함), 아니면 quiet. 무작위는 없다.

코드: `packages/team-engine/src/movement.ts`, `policy.ts`(`paceFor`, `audible`, `quietSlackMs`).

### 3.8 소음 읽기 — 가설에 대한 베이즈 갱신

소음은 방아쇠가 아니라 **가설의 근거**다. 수비는 "지금 맵에서 무슨 일이 일어나고 있는가"에 대한 사후확률을 유지한다.
사이트마다 역할이 하나씩 — **hit**(실제 타격), **show**(페이크의 쇼: 보이려고 낸 존재감), **quiet**(아무것도 없음) —
이고, 스파이크는 하나이므로 상태는 다음 넷 중 하나다.

```
none            전부 quiet (아직 안 움직였거나, 조용히 접근 중)
hit(t)          t에 실제 타격, 나머지 quiet
show(s)         s에서 쇼, 실제 목표는 아직 quiet (타격 전의 페이크)
hit(t)+show(s)  t에 타격, s의 쇼도 계속
```

**갱신.**  `P(S | e) ∝ P(S) · Π_사이트 L(e_사이트 | 그 사이트의 역할)^τ`

사이트별 근거(최근 창: 발소리 4초, 목격 8초, 사격·스킬 단서 10초):
`n` = 근거가 있는 적의 수 = max(들린 러너 수, 본 적 수), `c` = 접촉(목격 또는 사격·탄 궤적), `u` = 스킬 단서.

| 우도 | hit | show | quiet | 뜻 |
|---|---|---|---|---|
| `n ~ Binomial(N, p)` — N = 생존 적 수 | p = 0.80 | 0.35 | 0.03 | 실제 타격은 팀 대부분이 온다. 페이크는 소수. 조용한 곳엔 러커 하나 정도 |
| `c ~ Bernoulli(q)` | q = 0.85 | 0.15 | 0.03 | 실제 타격은 교전이 난다. 페이크는 교전을 피한다 |
| `u ~ Bernoulli(v)` (스킬이 있는 경기에서만) | v = 0.70 | 0.50 | 0.03 | 둘 다 스킬을 쓰지만 타격이 더 쓴다 |

사전확률:

```
P(none) ∝ 1          P(hit(t)) ∝ (1 − φ)·π_t
P(show(s)) ∝ ½φ · Σ_{t≠s} π_t/(K−1)          P(hit(t)+show(s)) ∝ ½φ · π_t/(K−1)
π_t = 상대가 치는 사이트 성향(라운드 간 모델)
φ   = 상대의 페이크 비율(라운드 간 모델) × 시계상 페이크 가능성
      페이크 비율 = (n_fake + 0.2·s) / (N + s)      — 자료가 없으면 기저율 0.2, s = 사전 강도
      가능성 = clamp((남은 시계 − T) / T, 0, 1),  T = 사이트 간 이동 + 설치   — 늦으면 페이크할 시간이 없다
τ   = ½ + 생존 수비의 decisionMaking 평균    — 패턴 인식이 좋은 팀은 근거를 더 날카롭게 반영(τ > 1)
```

페이크 관측: 수비가 2명 이상을 처음 듣거나 본 사이트(`shownSite`)와 설치 사이트가 다르면 페이크 1회, 같으면 정직한 타격 1회.

**대응은 믿음에 비례한다.**  `보내는 인원 = round(P(hit s) × 그 사이트에 배치되지 않은 생존 수비 수)`, 가까운 순.

| P(hit) (가용 3명) | 대응 |
|---|---|
| < 1/6 | 유지 |
| 1/6 – 1/2 | 지원 1명(로테이터), 먼 쪽 앵커는 남는다 |
| 1/2 – 5/6 | 2명 |
| ≥ 5/6 | 전원(스택) |

쇼라는 믿음이 강하면 아무리 시끄러워도 아무도 가지 않는다 — 확률 질량이 hit(s)가 아니라 show(s)에 있기 때문이다.
늘릴 때는 즉시, 줄일 때는 5초 뒤(발소리는 깜빡이지만 로테이션은 그렇지 않다). 로테이터는 사이트가 아직 유지되고 있으면
가장 빠른 진입로로 합류하고, 이미 넘어갔으면 리테이크와 같은 최소 노출 접근로의 집결 구역에서 기다린다. 해제되면 원래 자리로 돌아간다.
모든 변경은 계획에 사유와 함께 남는다: `"5 runners heard on B, no contact on A — P(hit B) 0.94, fake 0.06 — rotate 3"`.

| 근거 (5v5, 사전: φ 0.2, π 균등, τ 1 — 코드 계산값) | P(hit B) | P(fake) | P(none) | 대응 (가용 3명) |
|---|---|---|---|---|
| 아무것도 없음 | 0.00 | 0.01 | 0.99 | 유지 |
| B에 러너 1 | 0.00 | 0.10 | 0.90 | 유지 (러커로 읽음) |
| B에 러너 2, 접촉 없음 | 0.12 | 0.56 | 0.31 | 유지 (페이크로 읽음) |
| B에 러너 3, 접촉 없음 | 0.61 | 0.38 | 0.01 | 2명 |
| B에 러너 4, 접촉 없음 | 0.92 | 0.08 | 0.00 | 스택 3 |
| B에 러너 5, 접촉 없음 | 0.99 | 0.01 | 0.00 | 스택 3 |
| B에 러너 2 + 접촉 | 0.86 | 0.12 | 0.01 | 스택 3 |
| B에 러너 2, 상대가 페이크를 거의 안 함(φ 0.02) | 0.29 | 0.11 | 0.60 | 지원 1 |
| B에 러너 2, 상대가 페이크를 자주 함(φ 0.6) | 0.03 | 0.82 | 0.15 | 유지 |
| B에 러너 2, 페이크할 시계가 없음 | 0.33 | 0.00 | 0.67 | 지원 1 |

코드: `packages/team-engine/src/hit-belief.ts`, `policy.ts`(`gatherEvidence`, `readNoise`, `decideDefenseRotation`), `opponent-model.ts`.
우도의 숫자(p, q, v)와 P(none)의 가중치 1은 측정값이 아니라 위 표의 "뜻"을 옮긴 모델 가정이다.

## 4. 라운드 폼 (match-runner)

```
폼 k = 1 + σ·z + 압박 보정
σ = 0.08 · (1 − consistency),   z ~ N(0,1), ±2로 제한
압박 보정 = (clutch − 0.6) · 0.05      (매치포인트·연장 라운드에서만)
```

그 라운드의 모든 기계적 능력치에 `k`를 곱한다. consistency 1.0은 항상 제 실력, 0.4는 ±9.6%까지 흔들린다.

## 5.1 팀별 입력 — 맵 숙련도 · 스카우팅 · 게임 플랜 (시리즈 계층)

`MatchConfig.tuning`은 양 팀 공통이다. 시리즈 계층은 **같은 수식에 팀별·맵별 값**을 넣는다
(`MatchConfig.teamInputs[슬롯]`, `packages/match-runner/src/team-inputs.ts`). 결과에 직접 더하는 값은 없다.
상세·출처·측정값: `docs/SERIES_AND_VETO.md`.

### 맵 숙련도 M (0–1)

```
M = 0.5·H + 0.3·C + 0.2·F
H = min(1, E·2R)        E = n/(n+K_E),  R = 0.5 + n/(n+10)·(맵 승률 − 팀 전체 승률[→0.5로 수축])
C = 10개 쌍 평균  g_ij/(g_ij+3),   g_ij = min(g_i, g_j)      (g = 이 팀에서 이 맵을 뛴 경기 수)
F = max_조합  [5명↔5요원 최적 배정의 평균 커버리지] × [조합 수축 승률 ÷ 최고]
```

|---|---|---|---|
| H 전적 | 맵별 경기 수·승수(`map-history.json`, 2025 시즌 이후, 46팀) | 경기 수만(`mapPool`), 결과 항 R = 0.5 | `2E·sd(p̂)`; 승패 미상이면 sd = 0.15 |
| C 연속성 | 선수별 맵 출전 수(`map-history.json`) | `g_i = n × 출전 비율`로 배분 | 실측 0 / 배분이면 0.1 |
| F 조합 적합 | `map-comps.json`(풀의 9개 맵), 선수 역할, 요원 풀 | 역할 구성만(0.75/역할) | 0.05 / 역할만이면 0.15, 정보 없는 선수당 +0.02 |

### 숙련도 → 기존 수식의 값

`d = clamp(M − M₀, ±0.5)`, `M₀` = 리그 중앙값(현재 0.612). `d = 0`이면 전부 기본값.

| 수식 | 팀별 값 |
|---|---|
| 쓰로잉 해저드 (§3.3) | `λ₀' = λ₀ · e^(−2d)` |
| 라운드 폼 (§4) | `σ' = σ · clamp(1 − 1.2d, 0.5, 1.6)` |
| 정보 반감기 (§2.2) | `trading' = trading + 0.4d` |
| 양각 지연 (§2.1) | `gameSense' = gameSense + 0.4d` |
| 상대 모델 사전 의사카운트 α | `패턴 인식' = 인식 + 0.6d` |
