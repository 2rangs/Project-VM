**Collision analysis (`git diff --name-only main...origin/claude/pv-*`, pairwise `comm`):**
No two branches add the same file path. Root config (`package.json`, `pnpm-workspace.yaml`,
`pnpm-lock.yaml`, `tsconfig*`, `vitest.config.ts`, `.gitignore`) and all of
`packages/shared-types/` exist **only** on `pv-core`. Every sibling adds its own disjoint
`packages/<name>/` directory and its own docs (distinct filenames). **Merges are therefore
additive — expect no git textual conflicts.** The integration work is post-merge wiring,
not conflict resolution.

## 1. Recommended merge order

Merge `pv-core` first (it is the only branch with the pnpm workspace root + `shared-types`,
the shared vocabulary everything else mirrors), then the engine branches, then tooling/UI:

1. **`pv-core`** — root config, `shared-types`, simulation/decision packages, adapters.
2. **`pv-spatial`** — spatial/combat/perception/ability engines (the most depended-on engines).
3. **`pv-data`** — economy-engine + datasets/ + tools/ (priors, schemas).
4. **`pv-research`** — catalog-builder + sources/license docs (data only; no package graph).
5. **`pv-replay`** — replay-engine (+ desktop app when ready).
6. **`pv-mapmesh`** — map geometry/mesh assets.

Each step: merge (additive), then run the per-branch wiring in §2, then `pnpm install` +
`pnpm test` before the next branch.

## 2. Post-merge wiring (the real work)

### 2a. Package scope — rename `@project-v/*` → `@pv/*`
`pv-spatial` publishes its four packages under **`@project-v/*`**; the rest of the repo uses
`@pv/*`. Rename the four `package.json` `name` fields and every intra-spatial import, then
reference them as `@pv/spatial-engine` etc. (The integration-adapters mirrors already target
`@pv/<engine>` names — see §2c.)

### 2b. Replace `shared-mirror.ts` with real `@pv/shared-types`
`spatial`(combat/perception/ability), `economy-engine` and others each carry a
`src/shared-mirror.ts` copy of the shared types so they compiled standalone. Per package:
delete the mirror, add `"@pv/shared-types": "workspace:*"` to its deps, and repoint its
imports from `./shared-mirror.js` to `@pv/shared-types`. Verify the mirrored shapes still
match (they were written to match; any drift surfaces as a type error here).

### 2c. Swap integration-adapters mirrors for real imports
`packages/integration-adapters/src/*-adapter.ts` each hold a **structural mirror** with the
source branch + commit in its header. Replace each mirror interface with the real import and
delete the mirror block:
- `spatial-adapter.ts` → `import { SpatialEngine, MapCoordinateSystem } from "@pv/spatial-engine"`
- `combat-adapter.ts` → `import { monteCarloDuel, buildCatalog, requireWeapon } from "@pv/combat-engine"`
- `economy-adapter.ts` → `import { evaluateEconomy } from "@pv/economy-engine"`
- `ability-adapter.ts` → `import { checkAvailability } from "@pv/ability-engine"`
- `observation-adapter.ts` → `import { PerceptionEngine } from "@pv/perception-engine"`
Add the corresponding `workspace:*` deps. The adapters' public functions (`spatialQueryFromEngine`,
`combatEstimatorFromEngine`, …) keep their signatures, so downstream code is unaffected.

### 2d. Lockfiles & workspace membership
Each sibling package ships a standalone **`package-lock.json`** (npm). In a pnpm workspace
these are ignored and should be **removed** to avoid confusion; the root `pnpm-lock.yaml`
(owned by pv-core) is regenerated by `pnpm install` once all packages are members. The root
`pnpm-workspace.yaml` already globs `packages/*`, so merged packages join automatically —
no edit needed unless a package lives outside `packages/` (e.g. `apps/desktop`, `tools/*`):
add those globs then.

### 2e. Identifier / unit normalization
Apply `packages/integration-adapters/src/normalization.ts` at every boundary:
- **Agent slugs:** `kay-o` (PV-1/PV-2/game-rules) vs `kayo` (scenarios) → `normalizeAgentSlug`.
- **Team ids:** `team-N` (PV-3) vs `teamIdx 0|1` (PV-2/PV-4) → `teamIdToIdx`/`teamIdxToId`.
- **Coordinates:** ⚠️ **rehearsal-confirmed (F1, docs/archive/INTEGRATION_REHEARSAL.md):** PV-2
  minimapUnits are the **VLR minimap PIXEL frame** (x≈92..973, y≈117..844), NOT normalized
  ×1000. The ×1000 fallback mis-maps attacker-spawn→b-main. Inject PV-6's verified
  vlr-pixel↔game transform via `spatialQueryFromEngine(engine, { minimapToGame })`.
- **Time:** all ms (no conversion).
- **Eco/full thresholds:** PV-3 `ECO_BANK_THRESHOLD=2000` (bank credits) vs PV-2 priors
  `ecoMaxCredits=5000` (loadout value) — different metrics; reconcile when wiring economy.

## 4. Post-integration test commands
```bash
pnpm install
pnpm -r typecheck     # PER PACKAGE — a single root tsc fails (F4: pv-core strict flags vs
                      # siblings' looser configs). Do NOT use one root tsconfig over all.
pnpm -r test          # PER PACKAGE — siblings mix runners (F5: replay-engine uses node:test,
                      # others vitest). A single root vitest cannot run node:test files.
```
Expect pv-core's current suite (121 passed, 4 todo) plus each engine's own tests. The 4
`it.todo` scenarios (07–10 economy valuation) become real assertions once economy-engine is
wired through `economyEvaluatorFromEngine`.

## 5. End-to-end acceptance test (the integration goal)

Once `round-simulator` (PV-4) lands and the adapters are wired, add an e2e test that runs a
full Ascent round deterministically and validates the pipeline:

```
scenario_XX.json (PV-2)
  → loadDecisionContext (world-state)                     [initial WorldState]
  → PerceptionEngine.perceive → observationProviderForPlayer   [per-player Observation]
  → TeamDecisionPolicy(spatialQueryFromEngine(...), {economy: economyEvaluatorFromEngine(...)})
       .decide(view, seededRng)                           [PolicyDecision: strategy/roles/commands]
  → round-simulator tick loop (fixed-tick clock, SeededRng)
       executes ActionCommands via combat/ability/spatial engines
       → EventLog (simulation-core)                       [canonical round events]
  → validation harness (PV-2 baselines, docs/VALIDATION_BASELINES.md)   [stats sanity]
  → replay-engine convert-sim(EventLog) → replay          [replayable timeline]
  → Viewer / apps/desktop (PV-6)                           [visual check]
```

**Acceptance criteria:**
1. **Determinism:** same scenario + same master seed → identical EventLog (hash-stable) and
   identical replay (DECISION-010).
2. **Information boundary:** no agent command is derivable from enemy ground truth —
   `PolicyView` carries no WorldState (asserted today); audit that the simulator only feeds
   perception output to the policy.
3. **Feasibility:** no executed command violates a constraint the Action Generator would
   have excluded (e.g. a plant off a plant zone, a rotation that cannot finish in time).
4. **Economy valuation:** scenarios 07–10 produce the expected save/exit decisions once
   economy-engine is wired (promote the `it.todo`s).
5. **Stat sanity:** aggregate round outcomes over many seeds fall within PV-2's validation
   baselines (e.g. opening-duel / economy win-rate priors), not a pre-decided winner
   (DECISION-002).
