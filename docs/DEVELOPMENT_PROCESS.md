## 2. 운영 방식

### 2.1 오케스트레이터 + 하위 세션
- **오케스트레이터 세션 1개**(통합 브랜치 `claude/remaining-work-final-push-fa1459`)가 요청을 작업 단위로 쪼개 하위 세션에 맡기고, 결과를 검증해 main에 합친다.
- 하위 세션은 **자기 git worktree·자기 브랜치**에서 일하고 커밋만 한다. **push·main 머지는 하지 않는다**(오케스트레이터만).
- 브리핑에는 항상: 목표, 완료 기준(측정 가능한 수치), 소유 파일 범위(다른 세션과 겹치지 않게), 검증 명령, 금지 사항(라이선스·자산), 보고 형식.
- 세션 결과 보고는 **주장으로 취급**하고, 머지 전에 통합 브랜치에서 다시 측정한다(예: 14·15차 머지 때 160경기 재측정).
- 초기(11-18)에는 PV-1~PV-6 역할 분담(Research/Data/Core/Spatial/MapMesh/Replay), 이후에는 기능 단위 세션(balance-recovery, series-veto, ability-realism, maps-data/nav-engine, matchday-uiux, footstep-noise-belief, generated-people, career-shell, club-ops).

### 2.3 설계 규칙 (엔진)
- 결과는 이름 있는 공식으로: Hick–Hyman 크로스파이어 페널티, 정보 감쇠 `2^(−Δt/halfLife)`, Lanchester 제곱 법칙(리테이크/세이브), 비례 해저드 쓰로잉, 가우시안 라운드 폼, 디리클레 상대 모델, 발소리 베이즈 읽기, 기하학적 앵글 어드밴티지, 맵 숙련도 `M = 0.5H + 0.3C + 0.2F`, 이동 사격 정지 시간 등. 상세는 `docs/STAT_OUTCOME_MATRIX.md`, `docs/CONTINUOUS_TACTICAL_INTELLIGENCE.md`.
- 팀이 고를 수 있는 성향은 **경기 전 옵션**(`MatchConfig.tuning`, 최소 쓰로잉률 등). 세계의 물리적 결과(피커스 어드밴티지 등)는 옵션이 아님.
- 지표를 맞추려고 듀얼 확률·속도·전역 상수를 바꾸지 않는다. 지표가 틀리면 **측정한 원인**을 찾아 고친다(예: 14차 직전 오프닝 듀얼 실패의 원인 = 공격수가 첫 교전 98%에서 걸어 들어감).
- 전지적 판단 금지: AI는 팀의 믿음(관측·소리·상대 모델)으로만 판단.

## 3. 작업 환경 (이 Mac에서 실제로 필요했던 것)
- Node 22(`nvm use 22.13.1`), `npx -y pnpm@10.28.0 install --frozen-lockfile` (corepack pnpm은 서명 오류).
- `sim:validate`는 Python `jsonschema` 필요 → venv를 `PYTHON=`으로 지정.
- `file:` 의존성 사본이 오래되면 이상한 오류(`spikeBlastRadiusUnits is not a function`) → `pnpm install` 재실행.
- 데스크톱 e2e는 Playwright를 의존성으로 두지 않음 → `PLAYWRIGHT_REQUIRE_BASE`에 playwright가 있는 디렉터리. e2e가 `apps/desktop/docs/*.png`를 다시 그리므로 머지 전 되돌림.
- **무거운 실행은 한 번에 하나**(사용자 지시, 11-23): 시뮬 배치·e2e·앱 캡처·성능 테스트는 공용 잠금 `/Users/yi-rang/ProjectV-assets/tools/heavy-run.sh "<label>" -- <command>`로 실행. 동시에 돌리면 머신이 버거워지고 e2e 스크린샷 타임아웃·성능 테스트 실패가 났음.
- zsh: 따옴표 없는 변수는 단어 분리 안 됨(`${=cfg}`), 매치 없는 glob은 줄 전체 중단.
- `sim-batch`의 `--out`과 `--report`는 서로 다른 경로여야 함(같으면 즉시 종료).

## 5. 배운 것 (다음 개발자에게)
1. **세션 보고 ≠ 사실.** 통합 브랜치에서 다시 측정하면 다를 수 있다(부하, 시드, 다른 브랜치와의 상호작용).
2. **사실적인 기능이 지표를 먼저 떨어뜨린다.** 위치 기반 시야는 2/8까지 떨어뜨렸고, 원인(공격 동선이 노출을 모름)을 고치자 8/8이 됐다. 지표를 상수로 덮지 않은 덕분에 엔진이 실제로 좋아졌다.
3. **새 맵을 "자기 지형"으로 켜면 Ascent 전용 가정이 드러난다**(Haven 수비 0.61, Split 전멸 0.36). 맵 데이터만으로는 부족하고 맵별 전술 데이터가 필요하다.
4. **UI 요청은 사용자의 말 그대로를 확인.** "경로 따라가는 거 좀 그럼"은 레일 같은 움직임이 아니라 "벽을 가로지름"이었다.
5. **병렬은 파일 소유권과 머신 부하 둘 다 관리해야 한다.** 파일은 브리핑의 소유 범위로, 부하는 공용 잠금으로.
6. 20경기 배치는 노이즈가 크다(피스톨 40라운드). 판정은 160경기로.
7. **검증 도구도 테스트하라.** 160경기 판정이 몇 주 동안 평균 선수 미러 경기를 재고 있었다. 배치가 실제 팀을 불러오는지(능력치 분포가 평균 하나가 아닌지) 확인하는 테스트가 처음부터 있었어야 했다.
8. **main에 들어가는 길은 하나로.** 마지막 날 다른 세션이 별도 통합 브랜치(`claude/final-merge`)로 main에 푸시하면서, 각 세션의 마지막 커밋 일부와 e2e 진입점 수정이 빠졌다. 통합 담당을 한 곳으로 두고, 다른 세션은 브랜치까지만.
